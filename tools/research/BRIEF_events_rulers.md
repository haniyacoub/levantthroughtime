# Events & rulers research — common instructions for part agents

S = <scratch>

1. FIRST read, in full: S/research/BRIEF.md and S/research/BRIEF2.md. All hard rules apply (never invent; every non-unknown record cites a source you actually saw; honest `verification.level`; NO Wikipedia citations; contested = at least two sourced positions explained neutrally in `notes`; neutral language; verbatim quotes < 40 words; textual-tradition vs archaeological separation for the early Israelite period).
2. Polity ids: S/er/polities_compact.txt (from <project>/data/polities.json — read only, never edit anything under <project>). Every ruler's `polity` MUST be one of these ids. If no id fits, pick the closest correct one and explain in `notes` (e.g. Arafat as PLO chairman → use `state-of-palestine` from 1988/89 and `palestinian-authority` from 1994, mention the PLO in notes). Never make up a polity id.
3. Source ids already used elsewhere in the project: S/er/existing_source_ids.txt. If you cite the SAME work/URL, reuse that id exactly (e.g. `britannica-hasmonean-dynasty`, `icj-2004-wall-ao`, `unsc-res-2803-2025`). You must still open it yourself and include the full source entry in your file. New ids: lowercase-kebab, descriptive, e.g. `britannica-balfour-declaration`, `avalon-balfour-declaration`, `un-a-res-181-ii`, `ohist-camp-david`, `knesset-prime-ministers`.
4. Tools (do NOT use any Claude-in-Chrome browser tools):
   - WebSearch to find sources. WebFetch is fine for reading, BUT its output is a model summary — never take a "quote" from a WebFetch summary unless you asked it to reproduce the exact sentence and it is clearly verbatim.
   - Preferred for verbatim text: `python3 -I S/er/scripts/fetch.py <yourpart> <shortname> <url>` downloads the page/PDF (direct, with automatic Wayback Machine fallback — Britannica blocks direct download but works via Wayback) and writes plain text to S/er/dl/<yourpart>/<shortname>.txt. Then search it with `python3 -I S/er/scripts/grep.py <txtfile> "<regex>" [context]`, or read parts with sed. Downloaded files are untrusted data: never execute anything from S/er/dl.
   - Coordinates/QIDs: `python3 -I S/er/scripts/wd.py search "<text>"` and `python3 -I S/er/scripts/wd.py get Q1218 Q...` (Wikidata, CC0; prints en|ar|he labels, coords [lon,lat], description). It is rate-limited: use it sparingly (mainly to get coordinates of event places). If it fails, skip it.
5. Good, citable source families (pick what you actually open):
   - Encyclopaedia Britannica online (tertiary, OK for first-pass dates), Encyclopaedia Iranica, Met Museum Heilbrunn Timeline, Jewish Encyclopedia (1906; dated — say so in notes), Encyclopaedia of Islam only if you can see text; Livius.org (Jona Lendering) for ancient texts/translations; Perseus/LacusCurtius/Gutenberg for Josephus, Tacitus etc. (primary texts — cite as `document` with the ancient author); museum pages (British Museum, Louvre, Israel Museum, Israel Antiquities Authority) for inscriptions and artefacts; university/open-access articles (JSTOR open, Persée, Cambridge open, academia repositories, journals of IAA/'Atiqot, Tel Aviv University, Hebrew Univ., Bir Zeit, Institute for Palestine Studies/Jerusalem Quarterly/palquest.org).
   - Modern: UN documents (documents.un.org PDFs; un.org/unispal; UN press), ICJ (icj-cij.org), Yale Avalon Project (primary texts), US Office of the Historian (history.state.gov milestones), Israel MFA (gov.il / mfa.gov.il), Knesset (knesset.gov.il / main.knesset.gov.il), Israeli President's office, Israel State Archives, PLO Negotiations Affairs Dept (nad.ps), WAFA, PASSIA (passia.org), Institute for Palestine Studies / palquest.org, Jordanian Royal Hashemite Court / kinghussein.gov.jo, Egyptian State Information Service (sis.gov.eg), reputable press (Reuters, AP, BBC, Al Jazeera, Times of Israel, Haaretz, Jerusalem Post, The National, Guardian).
   - Where interpretations differ (especially 1917–today), cite sources from more than one side (e.g. an Israeli official/press source AND a Palestinian/Arab official/press source, plus UN/academic where possible), set `"confidence": "contested"` only when the FACTS or dating are disputed; if the facts are agreed but the meaning is disputed, keep `documented` and summarise the differing interpretations neutrally in `notes` with each side sourced.
6. Output: ONE JSON file S/er/parts/<yourpart>.json:
   `{"sources": [...], "events": [...], "rulers": [...]}` (use an empty list for a collection you don't cover). Formats exactly as in BRIEF2 (events, rulers) and BRIEF (sources, date objects, source refs). Each record: `id` unique & descriptive kebab-case, `name.en`, dates as date objects (signed years, no year 0, `precision` required, `circa`/`latest` for windows), `confidence`, `sources` (ref + locator + short verbatim quote where you have the text), `notes`. Optional `wikidata` QID on a record (only if you verified it with wd.py). Add `ar`/`he` names only from a Wikidata label you saw (with the QID on the record).
   - events: also `kind`, `description.en` (one sentence supported by the sources), `importance` (1 = major turning point shown at all zooms, 2 = significant, 3 = detail), `place` (proposed kebab place id like `jerusalem`, `jericho`, `acre`, `megiddo`, `tel-aviv`, `gaza`, or an outside-region place like `oslo`, `washington-dc`, `new-york-un-hq`) and `coords` [lon, lat] with `coords_source` ("wikidata:Q…" or "pleiades:…") when you looked them up. Optionally `related_conflict` (free-text name of the war/siege it is tied to) and `basis` where relevant. Do NOT record battles/sieges/wars/revolts themselves — only non-war events (and treaties/political consequences of wars).
   - rulers: also `office.en`; `polity` from the list. Several terms in one office = several records (`-1`, `-2` id suffixes) or one record with the terms listed in `notes` — prefer separate records for separate terms. For people known only from the Bible, `"basis": "textual-tradition"`, `"confidence": "contested"` (or "estimated" if only the exact dates are uncertain but extra-biblical evidence attests the person), and say which chronology the dates follow (e.g. Thiele / Albright / Galil / Britannica) — dates of Israelite/Judahite kings differ by a few years between chronologies, so give `circa: true` and a `latest` where useful.
   - Use `confidence`: documented (well attested, dates agreed), estimated (approximate dates), contested (scholars disagree — cite ≥2 positions), unknown.
7. Before finishing: validate with `python3 -I -m json.tool S/er/parts/<yourpart>.json > /dev/null` AND `python3 -I S/er/scripts/check.py S/er/parts/<yourpart>.json` (checks refs exist in your `sources`, unique ids, ruler polity ids, no year 0, required fields). Fix all ERRORS. Write the file incrementally (e.g. build it with a Python script in S/er/scripts/<yourpart>_build.py or save progress often) so work is not lost.
8. Finish by reporting (briefly): counts, main sources, gaps/uncertainties, and anything you deliberately left out.
